Design spec · Today, Process and the email reader · 2026-09-27

Morning Edition

The Morning Edition direction, with a Process tab. Today is the overview and Process is where you work through the queue, so Jon chooses the mode. Emails keep their own design: Cockpit designs everything around the message and never re-typesets the message itself. Decisions: DECISIONS §31.

Three directions were explored on 2026-09-26: Morning Edition (editorial), Instrument (a dense dashboard) and Native, refined (grouped system lists). Morning Edition was chosen; Instrument was rejected as "a productivity console".

01 · Today and Process

Two modes you choose between

Today is the overview: see the shape of the morning, glance at anything, and clear what doesn't need reading. Process is the queue: one list in section order, and you work straight down it. Because they're system tabs, each keeps its own scroll position and selection.

Quick look · a headline tapped on Today
Process · the queue, on a letter

Quick look opens large, straight away. It follows §25's pane rules: no half-height step, a zoom transition from the row, and the web view preloaded on tap.

Clear without opening. Today rows keep swipe and context-menu actions (Archive, Later, Trash), so you can clear things from the overview.

Both tabs read the same queue. Archive something in Process and it disappears from Today too, following the existing "disappear, with Undo" rule.

The custom back button goes away. Today no longer swaps itself out for the reader (the isReading switch in TodayView). Switching tabs replaces it.

02 · Newsletters

The sender designs the page, Cockpit designs the desk

The original HTML renders unchanged, with its images, fonts and layout, at the text size you've set for that sender. Cockpit draws the ground around it, the strip above it, and the footer below it.

One exception to keep in mind: letters with no design.

Mail from a person is usually bare HTML with no width of its own, which is why the current reader runs about 170 characters a line. For those, Cockpit only caps the width at a reading measure and adds side margins. The fonts, bullets and links stay exactly as sent. It's a container rule applied from outside the email, so it doesn't break §25. Designed newsletters set their own width and are never touched.

Text size stays per sender. The existing Text Size menu remains; the strip shows the current size, and ⌘+ and ⌘− adjust it.

The ground frames the email. In dark mode the ground goes dark and a light email reads as a sheet of paper on it, instead of a white glare filling the whole pane.

The footer is where Process continues. Custody line, then the next item, then "Archive and continue", which is the existing archive-and-advance.

The body is a stand-in. The text is Montaigne (public domain), and the banner, image and button are drawn to look like a typical designed newsletter.

03 · The rule

Apple draws the frame, Cockpit draws the page, the sender draws the email

If iPadOS has a control for it, use the system one with only the tint changed. Theme work touches Cockpit's own content. The email itself belongs to whoever sent it.

One accent, set in one place

The accent is one AccentColor color set in the asset catalog, with light and dark values, named as the app's global accent in project.yml. iPadOS uses it as the tint everywhere. Theme.accent is Color.accentColor, and the chip fill and chip text are mixed from it in code. To change the accent, change that one color set.

Cockpit has no asset catalog yet; the foundation slice adds it. If the accent ever changes, check that the mixed chip text still has enough contrast.

04 · Finding letters that ask something

No model call on retail mail

For you is already a free filter. Only personal mail reaches the step that decides whether it asks for something. That's a handful of emails a day, and they can be judged on the device.

1 · Rules

Every message · free

Already runs today: List-ID routing, bulk headers, the Promotions tab, the transactional check.

  • Offers, newsletters and bills stop here.
  • What's left is For you: mail from a person.
  • Cheap extra signals: a question mark in the new text, sent directly to you, a thread you've replied in.

Enough on its own to sort letters first.

2 · On-device

For you only · free

Apple's on-device model answers one narrow question at ingest: does this ask Jon to answer or do something, and what? It also pulls out dates offered and attachments mentioned.

  • Roughly 3–10 messages a day, private, no cost.
  • Same pattern as the on-device offer summary (Sep 23 amendment).
  • If the model fails, the letter still shows, just without the chip.

Adds the "Asks for a reply" chip and the dates strip.

3 · Frontier

Never automatic

Unchanged: no automatic Gmail fetch calls a frontier model.

Not needed for this feature.

Build the layout so it works with rules alone. Put step 2 behind a Settings switch, run it for a week to judge it, then turn it on. It's a new per-message judgment, so the architect writes a DECISIONS entry and a JUDGMENT-CONTRACT clause for it.
